- `createMilestoneRouter` requires Prisma, `getAuthContext`, `requireSession`, `requireSupervisor` and `requireMutation`. No protection is optional; construction rejects missing functions. Production composition binds the real session resolver/guards, with `requireRole('supervisor')` supplying the role guard. Order: session -> role -> source/CSRF -> JSON -> payload -> scope -> write.
- `MilestoneService` uses the explicit session-derived userId/role. Creation validates unknown input through `shared/milestones.mjs`, locks only the assigned supervisor's team, rechecks scope and compares dueAt to the DB wall clock after locking. Every mutation query uses one transaction client. Errors expose safe 400/401/403/404/415/503 envelopes; foreign/missing detail responses match.
- List/detail return the canonical Milestone DTO plus `meta.serverTime`. Latest submission is the highest version with that submission's feedback count. Read queries are scoped and use a repeatable-read transaction; lists order by dueAt then id. These are read models, not revision/feedback endpoint implementation.
- Client and API import the same pure `shared/milestones.mjs` module and declarations. Preserve that directory alongside `server/dist` at runtime. No new npm dependency/lockfile or schema migration is introduced.
- `sessionStore.readDomain` retains read metadata; `sessionStore.mutate` sends the current in-memory CSRF token and rejects stale results/account changes. Both use no-store/same-origin credentials and clear private state on 401. API field errors remain available to forms.
- UI routes are `/teams/:id`, `/teams/:id/milestones/new` and `/milestones/:id`. Student overview shows its real milestone track; supervisor team pages offer creation. All routes still recheck authorization at the server. Return-to allows these implemented internal routes only.
- Datetime-local is explicitly interpreted as Asia/Bangkok, with HH:mm meaning seconds 00. Input validation counts trimmed Unicode code points; no UTF-16 maxlength truncates valid titles. Saving is guarded against duplicate UI submission; an unknown mutation outcome requires checking the list before trying a new create.
- Empty/loading/field/error/retry/private-denial states, mobile layout and keyboard focus reuse the existing monochrome design. No inert submission, feedback, revision, edit or cancel controls are exposed.

`npm run test:b01:isolated` provisions only new disposable databases and runs ordinary, auth, G1, milestone and upgrade checks. `npm run review:b01` additionally serves the compiled app; `npm run review:auth:stop` performs graceful cleanup. [Actual evidence](../evidence/R1-B01-A-review.md) distinguishes seven retained service cases, 26 new real-session cases, real browser observations and pending human acceptance.
